# CyberWikiBench 题库数据标准

## 目的

本标准定义 CyberWikiBench 的唯一题目交换格式。题库维护、benchmark 评测、RAG 索引和 Chrome 做题助手都读取同一份结构化题目数据，避免不同系统各自维护答案。

`data/questions.jsonl` 是可追加的规范源格式；`data/questions.json` 是由 JSONL 生成、便于一次性加载的聚合文件。每次修改题目后，都必须通过校验器。

## 文件与编码

| 文件 | 用途 |
| --- | --- |
| `data/questions.jsonl` | 一行一题；新增题目时优先维护此文件。 |
| `data/questions.json` | 带数据集元信息的聚合 JSON，不应手工编辑。 |
| `data/parse_report.json` | 解析数量、题型和答案分布报告。 |
| `schemas/question.schema.json` | 机器可读的 JSON Schema。 |

所有文件使用 UTF-8（无 BOM）、LF 换行。ID 一经发布不得修改或复用。

## 通用字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 稳定、小写 slug，例如 `cwkb-0001`。 |
| `type` | enum | 是 | `single_choice` 或 `true_false`。 |
| `stem` | string | 是 | 题干；可包含多行命令、表格和代码。不得含“正确答案”或箭头标记。 |
| `options` | array | 是 | 单选题为 2～6 个 `{key,text}`；判断题为 `[]`。 |
| `answer` | string / boolean | 是 | 单选题是选项键，如 `"B"`；判断题是 `true` 或 `false`。 |
| `source` | object | 是 | 原始来源、来源内题号和引用文件/链接。 |
| `metadata` | object | 是 | 领域、难度、标签、版本和质检状态。 |
| `explanation` | string / null | 是 | 经过审核的答案解析；未撰写时为 `null`。 |
| `evidence` | array | 是 | 权威依据数组；未补充时为 `[]`。 |

`metadata.quality_status` 只能是：

- `unreviewed`：已入库，尚未人工复核。
- `verified`：题目、答案和依据已核验。
- `questionable`：存在歧义、版本依赖或待确认问题。
- `rejected`：不参与任何评测或检索。

`metadata.difficulty` 使用 1～5：1 为直接记忆，3 为常规应用，5 为多步排障或复杂推理。厂商命令、协议和法规类题目必须填写 `metadata.version`，例如 `"Huawei VRP V8"`。

## 单选题示例

```json
{
  "id": "cwkb-extra-0001",
  "type": "single_choice",
  "stem": "在 WLAN 基础组网中，WLAN 网关的作用是（ ）。",
  "options": [
    {"key": "A", "text": "执行无线访问点的管理功能"},
    {"key": "B", "text": "提供对有线网络的接入"},
    {"key": "C", "text": "连接无线网络与外部网络（如互联网）"},
    {"key": "D", "text": "负责配置 WLAN 客户端的安全性"}
  ],
  "answer": "C",
  "source": {
    "collection": "人工补充题",
    "source_item_id": 1,
    "reference": "authoring/2026-q3.jsonl"
  },
  "metadata": {
    "domain": "wireless_network",
    "subdomain": "wlan_architecture",
    "difficulty": 1,
    "reasoning_types": ["concept"],
    "tags": ["wlan", "gateway"],
    "version": null,
    "quality_status": "verified"
  },
  "explanation": "WLAN 网关承担无线网络与外部网络之间的连接和转发。",
  "evidence": [
    {"title": "教材章节", "locator": "第 3 章", "url": null}
  ]
}
```

## 新增题目流程

1. 在 `data/incoming/` 创建一个 JSONL 文件，一行一个题目，按上述格式填写。
2. 分配从未使用过的 ID。来源内题号应保留原始编号；人工题可从 1 开始。
3. 不得在 `stem`、`options` 中写入答案标记、解析或“正确答案”。
4. 补齐领域、难度、标签；厂商/版本敏感题补齐 `version` 和依据。
5. 运行校验：

   ```powershell
   & "C:\Users\Garyyang\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" scripts/parse_question_bank.py --validate-jsonl data/incoming/your_batch.jsonl
   ```

6. 人工复核通过后合并到 `data/questions.jsonl`，重新生成聚合 JSON 与报告：

   ```powershell
   & "C:\Users\Garyyang\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" scripts/parse_question_bank.py --build-jsonl data/questions.jsonl --out-dir data
   ```

7. 更新 benchmark 的语义簇和数据分区；如果该题已被公开或用于隐藏测试，必须保留原 ID 并记录变更原因。

## Benchmark 与助手的隔离规则

- 隐藏测试题及其答案不得进入 Chrome 助手的精确题库或向量库。
- 闭卷 benchmark 禁用题库匹配、RAG、网页搜索和外部工具。
- 开卷 benchmark 只使用指定版本的资料库，并记录检索片段和知识库版本。
- 正式题目替换选项顺序时，必须同时更新 `answer`，保留题目 ID 并记录变更原因。
